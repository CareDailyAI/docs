# Synthetic API: Daily Report

The `dailyreport` is a **time-series state variable**, generated by the `reports` microservice package (`com.ppc.Microservices/intelligence/reports/`) from events that bots add through the `report_add_event` data stream address. Events are cached by the bot and synthesized into a report (with optional LLM narrative) about 10 minutes after occupants wake up. On Sundays a weekly edition replaces the daily report and is also saved to `weeklyreport`; on the first Sunday of the month a `monthlyreport` is generated as well.

The original `daily_report_entry` address and section-ID based `com.ppc.Microservices/intelligence/dailyreport` package are deprecated. That package no longer registers any microservice, so `daily_report_entry` messages are not processed. `com.ppc.Bot/signals/dailyreport.py` is kept as a backwards-compatibility shim that maps legacy section IDs onto the event types below.

Event type constants (`EVENT_TYPE_*`) are defined in the same file, for example `sleep.wakeup`, `sleep.bedtime`, `activity.movement`, `bathroom.visit`, `medication.taken`, `it.device_offline`, `alert.warning`.

## Inputs

Data Stream Address : `report_add_event`

Bots normally add events through `signals.report.add_event()` (`com.ppc.Bot/signals/report/report.py`), which builds this message.

#### Properties
| Property | Type | Description |
| -------- | ---- | ----------- |
| event_type | String | Required. Event type, e.g. `sleep.wakeup`. The prefix selects the report section. |
| comment | String | Required. Text description of the event. |
| criticality | String | `info`, `warning`, or `critical`. Defaults to the schema default for the event type prefix. |
| timestamp_ms | int | Optional timestamp in milliseconds. Defaults to the current time. |
| identifier | String | Optional identifier to come back and replace this event later (upsert). Without an identifier, a new event with the same `event_type` within 1 hour 15 minutes of an existing one overwrites it. |
| event_types | List | Optional list of event types for multi-faceted events. Defaults to `[event_type]`. |
| event_id | String | Optional short unique ID generated by the signal helper. |
| category | String | Optional routing category, filled in from the schema by the signal helper. |

#### Content
Example data stream content to add an event to the report
```
{
    "event_type": "sleep.bedtime",
    "comment": "Went to sleep.",
    "criticality": "info",
    "timestamp_ms": timestamp_ms,
    "identifier": identifier,
    "event_types": ["sleep.bedtime"]
}
```

#### Legacy input (deprecated)

Data Stream Address : `daily_report_entry` with `section_id`, `comment`, `subtitle`, `identifier`, `include_timestamp`, `timestamp_override_ms`. Only the deprecated `dailyreport` package handled this address. Legacy `section_id` values map to event types through `com.ppc.Bot/signals/dailyreport.py` (for example `sleep` -> `sleep.summary`, `notes` -> `alert.info`, `system` -> `it.device_offline`).

## Outputs

Time-series State Variable : `dailyreport`

Also produced: `weeklyreport` (Sunday weekly edition, which is also stored as that day's `dailyreport`) and `monthlyreport` (first Sunday of each month). On-demand reports requested through `report_generate` are stored at `report_{report_name}` (for example `report_24hour`, `report_12hour`).

The time-series timestamp of a daily or weekly report is midnight (local time) at the start of the day the report was generated.

#### Properties
| Property | Type | Description |
| -------- | ---- | ----------- |
| title | String | Title of the daily report (the location name, upper-cased) |
| subtitle | String | Description of this daily report, e.g. "Daily Report for Monday December 29, 2025" |
| created_ms | int | Timestamp in milliseconds of the end of the reporting window (when the report was generated) |
| period | String | Report period: `dailyreport`, `weeklyreport`, `monthlyreport`, `report_24hour`, `report_12hour`, or `report_{name}` |
| sections | List | List of sections to the daily report, pre-sorted by weight, each with a list of items. The `summary` section is always first. |
| {section}.weight | int | Weight of this section, allowing the bot to pre-sort sections before saving the state variable so the app does not have to do this work. |
| {section}.id | String | Section ID (event type prefix, see above) |
| {section}.title | String | Title of this section |
| {section}.description | String | Static description of the section from the schema, recommended as the section subtitle |
| {section}.icon | String | Recommended icon for this section (FontAwesome name) |
| {section}.color | String | Recommended color for this section, hex without `#` |
| {section}.items | List | List of items that happened, pre-sorted by timestamp_ms |
| {item}.timestamp_ms | int | Timestamp in milliseconds of this entry. Absent on LLM-synthesized section items. |
| {item}.comment | String | Description of what happened at this time with the time description included at the beginning. This was the original daily report entry design, and is left here for backwards compatibility. On LLM-synthesized sections, items carry only a `comment`. |
| {item}.timestamp_str | String | Human-readable timestamp, e.g. "9:41 PM" (day of week is no longer included). Absent on LLM-synthesized items. |
| {item}.comment_raw | String | Raw comment without a timestamp |
| {item}.event_type | String | Event type that produced this item. Absent on LLM-synthesized items. |
| {item}.criticality | String | `info`, `warning`, or `critical`. Absent on LLM-synthesized items. |

#### Content
```
{
  "title": "ILENE JOHNSON",
  "subtitle": "Daily Report for Monday December 29, 2025",
  "created_ms": creation_timestamp_in_milliseconds,
  "period": "dailyreport",
  "sections": [
    {
      "id": "summary",
      "weight": -100,
      "title": "Today's Summary",
      "description": "Daily overview and key highlights.",
      "icon": "clipboard-list",
      "color": "694fee",
      "items": [
        {
          "timestamp_ms": timestamp,
          "comment": "Today: Slept about 8 hours with two bathroom visits overnight and normal daytime activity.",
          "comment_raw": "Today: Slept about 8 hours with two bathroom visits overnight and normal daytime activity."
        }
      ]
    },
    {
      "id": "alert",
      "weight": 0,
      "title": "Today's Alerts",
      "description": "Urgent notifications and reminders for the day.",
      "icon": "comment-exclamation",
      "color": "D0021B",
      "items": [
        {
          "timestamp_ms": timestamp,
          "comment": "2:27 AM - Fall detection learning is complete.",
          "comment_raw": "Fall detection learning is complete.",
          "timestamp_str": "2:27 AM",
          "event_type": "alert.info",
          "criticality": "info"
        }
      ]
    },
    {
      "id": "sleep",
      "weight": 15,
      "title": "Sleep",
      "description": "Sleep quality and other insightful information.",
      "icon": "moon",
      "color": "3d597c",
      "items": [
        {
          "timestamp_ms": timestamp,
          "comment": "9:41 PM - Went to sleep.",
          "comment_raw": "Went to sleep.",
          "timestamp_str": "9:41 PM",
          "event_type": "sleep.bedtime",
          "criticality": "info"
        },
        {
          "timestamp_ms": timestamp,
          "comment": "5:59 AM - Woke up",
          "comment_raw": "Woke up",
          "timestamp_str": "5:59 AM",
          "event_type": "sleep.wakeup",
          "criticality": "info"
        },
        {
          "timestamp_ms": timestamp,
          "comment": "5:59 AM - 8.3 hours of sleep.",
          "comment_raw": "8.3 hours of sleep.",
          "timestamp_str": "5:59 AM",
          "event_type": "sleep.duration",
          "criticality": "info"
        }
      ]
    }
  ]
}
```

When LLM synthesis is enabled and a section has enough events, that section's `items` are replaced by synthesized entries containing only a `comment` (a short summary followed by supporting detail bullets).

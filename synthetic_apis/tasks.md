# Synthetic API: Tasks

Tasks are to-do items shared by the people in a location. A person can create a task, optionally assign it to someone else in the Trusted Circle, give it a due date, and later mark it complete.
The bot stores the tasks, narrates changes to the History, and notifies the people involved.

Tasks are provided by the `tasks` microservice package. The companion `tasks_system` package automatically creates and removes system tasks (for example "Add People to your Trusted Circle.") as the location is set up.

## **Input** : Data Stream Messages

| Address | Description |
| ------- | ----------- |
| `update_task` | Add a new task or update an existing task. |
| `delete_task` | Mark an existing task complete and remove it. |

The task `id` is generated by the app (a UUID is recommended). System tasks created by the bot use ids that begin with a double underscore (`__init__`, `__people__`, `__ecc__`, `__oobe__`).

#### `update_task` Content

| Property | Type | Description |
| -------- | ---- | ----------- |
| id | String | Required. App-generated unique ID for this task. A message with no `id` is rejected. |
| title | String | Title of the task. Required to add or update a task. If `title` is missing and the task already exists, the task is treated as complete and deleted. |
| comment | String | Optional. Longer description of the task. |
| due_display | String | Optional. Human-readable due date to display, for example "Friday, October 11". |
| due_date | String | Optional. Due date in `YYYY-MM-DD` format. |
| assigned_to | Integer | Optional. User ID of the person this task is assigned to. Must be a user in this location, otherwise the field is dropped. |
| created_by | Integer | Optional. User ID of the person who created or updated the task. Must be a user in this location, otherwise the field is dropped. |

Keys with a `null` value are removed from the content before it is stored. Any other keys are stored on the task untouched.

```
{
  "id": "d86b00c0-ef4a-4e47-9adc-845a5dda53e0",
  "title": "Take mom to the doctor",
  "comment": "Amanda, mom has a neuro apt coming up. Can you please take her?\n\nProvidence Hospital\n1816 NE 32nd Ave\nSeattle, WA 98580",
  "created_by": 761656,
  "assigned_to": 35,
  "due_display": "Friday, October 11",
  "due_date": "2019-10-11"
}
```

#### `delete_task` Content

| Property | Type | Description |
| -------- | ---- | ----------- |
| id | String | Required. ID of the task to mark complete. |
| deleted_by | Integer | Optional. User ID of the person who completed the task, used in the History narrative and to notify the task's creator. |

```
{
  "id": "d86b00c0-ef4a-4e47-9adc-845a5dda53e0",
  "deleted_by": 35
}
```

#### Side effects

* Adding a task narrates "Task created" to the History and, when `assigned_to` is set, sends a push notification to the assignee. If the assignee has no app, an SMS with app download instructions is sent instead.
* Updating a task narrates "Task created" with an "updated" description and notifies the assignee.
* Completing a task narrates "Task completed" to the History, records it in the daily report, and notifies the creator when someone else completed it.
* When care services are enabled, the bot creates a first `__init__` task ("Learn how to create tasks.") the first time an Entry Sensor is added.

## Output

State Variable : `tasks`

Dictionary of the active tasks in this location, keyed by task `id`. Completed tasks are removed.

#### Properties

| Property | Description |
| -------- | ----------- |
| title | Title of the task. |
| comment | Longer description of the task. |
| due_display | Human-readable due date, if provided. |
| due_date | Due date in `YYYY-MM-DD` format, if provided. |
| assigned_to | User ID the task is assigned to, if provided. |
| created_by | User ID that created the task, if provided. |
| created | Timestamp in milliseconds when the task was added. Set by the bot. |
| updated | Timestamp in milliseconds when the task was last added or updated. Set by the bot. |
| priority | System tasks only. 0 = detail, 1 = info, 2 = warning, 3 = critical. |
| icon | System tasks only. Icon to render. |
| icon_font | System tasks only. Icon font package. See the Icon Font list in the README.md |
| url | System tasks only. When present, tapping the task should open this URL instead of the task details. `${appUrlScheme}` is a placeholder for the app's URL scheme, for example `${appUrlScheme}://main/people/addPerson`. |
| editable | System tasks only. False means the user cannot edit this task. |

## System Tasks

The `tasks_system` package creates and removes the following tasks automatically. Apps do not need to create them, but should render them like any other task.

| id | Title | Created when | Removed when |
| -- | ----- | ------------ | ------------ |
| `__people__` | Add People to your Trusted Circle. | Fewer than 2 users are in the location. | 2 or more users are in the location. |
| `__ecc__` | Set up the Emergency Call Center. | Emergency call center status is 1 (available but not enough information). | Emergency call center status is 3 (registered). |
| `__oobe__` | Add Devices. | No gateway, radar, bed, or button device is in the location and no device pack is installed. | A qualifying device is added or a pack installation completes. |
| `__init__` | Learn how to create tasks. | Care services are enabled and the first Entry Sensor is added. | The user marks it complete. |

#### **Input** : `update_device_bundles`

Apps report device pack (bundle) installation progress with the `update_device_bundles` data stream message. The content is a dictionary of pack model IDs to installation status, and it is stored in the `device_bundles` state variable. The pack model IDs a bot recognizes are listed in `PACK_INSTALLATION_MODEL_IDS` in `domain.py`.

| Status | Meaning |
| ------ | ------- |
| -1 | Installation started |
| 0 | Installation incomplete |
| 1 | Installation complete |

```
{
  "pack_model_id": 1
}
```
